## Competitors

### GitGuardian
- self_serve: **freemium-then-sales** | covers Claude Code terminal: **partial** | pricing: Free: $0 for teams up to 25 developers (unlimited real-time scanning, ggshield CLI, VS Code extension, git hooks). Business (25–200 devs): ~$18/dev/mo (one public data point; product-marketing-context.md cites $30–117/dev/mo range; Vendr reports $45,195 median annual contract across 31 purchases, range $19,800–$58,254 — Business tier pricing requires "Let's Talk" sales contact). Enterprise (200+ devs): fully custom, self-hosted option adds 15–30% premium. Implementation/professional services add $5,000–$25,000. Multi-year deals yield 15–25% discounts.
- gap vs CCGuard: GitGuardian's Claude Code integration is a point solution for one threat vector (credential exposure) delivered via opt-in CLI hooks that a developer must choose to install. CCGuard's exploitable gap is everything outside that narrow perimeter: (1) FULL SESSION TRANSCRIPT CAPTURE — GitGuardian sees three hook checkpoints; CCGuard parses full conversation context, giving employers genuine visibility into what AI-assisted work actually happened; (2) WORK-VS-PERSONAL ATTRIBUTION — CCGuard's 'donut' is the only mechanism anywhere that classifies whether a Claude Code session was company work or personal freelancing on company time and budget; no competitor including GitGuardian has any analogue; (3) AI SPEND GOVERNANCE AND ENFORCEMENT — CCGuard's proxy can enforce usage limits and warm-block over-allowance personal sessions; GitGuardian has no budget or enforcement layer; (4) COMPLIANCE AND EVIDENCE LAYER — eDiscovery, DPIA generation, retention policies are entirely outside GitGuardian's product scope; (5) SELF-SERVE SMB VACUUM — GitGuardian's free tier ends at 25 devs and Business requires sales; CCGuard can own card-pay self-serve for 10–200-dev startups that want session governance (not just secrets scanning) without an enterprise procurement process. The positioning line writes itself: 'GitGuardian tells you if a secret leaked. CCGuard tells you what your developers asked the AI to build, on whose time, and at what cost.'

### Snyk

- gap vs CCGuard: Snyk's entire product stack — including the new Evo ADS — operates on code artifacts and agent tool-call metadata. Finally, Snyk's self-serve hard wall at 10 developers and the $105/dev/mo Ignite jump leaves the 10–50 developer team (CCGuard's sweet spot ICP: security lead or eng manager at a 20–200-dev company) severely underserved by Snyk's GTM.

### Semgrep
- self_serve: **freemium-then-sales** | covers Claude Code terminal: **partial** | pricing: Free tier: up to 10 contributors and 10 private repos (full platform, no credit card). Teams: $30/contributor/month per module — Code (SAST) $30, Supply Chain (SCA) $30, Secrets $15; full stack costs ~$75/contributor/month. - gap vs CCGuard: Semgrep Guardian catches security bugs IN the code that Claude Code writes. CCGuard governs the Claude Code SESSION itself — what was sent to the AI, what secrets were exposed in prompts and context before any file was written, who used AI on what repo, what it cost the company, and whether that usage was for company work or a personal project. These are orthogonal layers: Semgrep scans the artifact (the file), CCGuard captures the interaction (the session). Specifically: (1) Semgrep has no secrets-in-prompt interception — it only finds hardcoded secrets after they appear in a file; CCGuard's proxy intercepts them before they leave the machine. (2) Semgrep has zero AI spend visibility or work/personal attribution — CCGuard's unique "donut" feature is completely unaddressed. (3) Semgrep has no employer-facing compliance evidence (eDiscovery, retention, DPIA) — CCGuard's enterprise layer covers this. (4) Semgrep's paid tier requires a sales call, leaving a 10-contributor ceiling on self-serve; a CCGuard free-tier wedge (solo dev self-audits own sessions, no credit card, immediate terminal visibility) can undercut Semgrep's PLG motion by being truly self-serve at the session level where Semgrep does not operate. Position CCGuard as the governance layer BENEATH Semgrep: "Semgrep audits your code; CCGuard audits your AI sessions — run both."

## Demand by wedge

### Secrets / credential leakage via AI coding tools (Claude Code / Cursor / Copilot sessions, prompts, config dirs, AI-generated commits) — score 5/10, self-serve fit medium
- who: Two personas. Acutely (the buyer): AppSec / DevSecOps / platform-security engineer at a 20-200-dev company who must answer "how are we stopping keys leaking into Cursor/Copilot/Claude Code?" for a policy, SOC2 audit, or after an incident. Secondarily and more emotionally (the user, not the buyer): the solo/indie or vibe-coding dev who got bill-shocked or saw their API key end up in a Cursor/Claude SQLite store or an AI-generated commit. The first has budget but needs IT/legal; the second feels acute pain but reaches for a free CLI.
- intent: Genuinely searched-for, not educate-into-existence — this is the strongest part of the case. Direct question-form demand exists: r/devops "How do you prevent credential leaks to AI tools?", ai.stackexchange "For teams using AI coding assistants (Copilot/Cursor), how are you preventing secrets from leaking into prompts?" (asked unprompted ~2 months ago), and multiple Facebook dev-group posts with the identical title. People are also searching solutions ("scan Cursor/Claude chat history for leaked API keys") and finding OSS tools. Vendors (GitGuardian, Doppler, Netwrix) are publishing SEO content against these queries, which confirms commercial search volume. Caveat: a large share of the adjacent search volume (the $82k/$55k/$19k "stolen API key bill" threads) is about keys leaked to public GitHub/git, NOT specifically through AI-tool sessions — high-emotion but a different root cause whose answer is "rotate + budget cap + vault," not a monitoring SaaS.
- existing: Crowded and partly free. (1) Incumbents extending into the exact wedge for free: GitGuardian "ggshield AI hooks" + "Agent Skills" (April 2026) scan prompts/commands/file-reads in Cursor/Claude Code/Copilot in real time, free on all plans; GitGuardian/Snyk/Semgrep already own post-commit secret scanning ($30-117/dev, $52-98/dev, $35/contributor). (2) Free OSS/indie point tools for the AI-session angle specifically: Sieve (macOS, scans Cursor/Claude/Copilot/Cline chat history, HN), claudleak/ironPeak CLI, an open-source Python CLI ("scans your Claude Code history for leaked API keys and redacts them in place, fully offline"). (3) Enterprise AI-DLP/governance: Microsoft Purview, Teramind, Netskope, Prompt Security, Cyberhaven, Nightfall, WitnessAI. (4) The free baseline fix everyone repeats: add .claude/.cursor to .gitignore, use a vault (Doppler/Azure Key Vault/SOPS), pre-commit hooks, short-lived/rotated creds. Named-tool gap: there is NO dominant paid tool branded specifically as "secret leakage for AI coding sessions" — but that gap is being filled by GitGuardian-for-free and OSS, which is worse than an empty gap.
- WTP: Weak for a standalone self-serve product; real only when bundled into a broader platform. Budget exists in the broader category — GitGuardian commands $30-117/dev/mo (~$45k ACV), Snyk $52-98/dev, Purview $10-60/user — but the AI-coding-secrets capability is precisely what those vendors are now giving away free as a feature, which collapses standalone pricing power. Individual devs' demonstrated WTP is ~$0 (they install free CLIs / fix .gitignore). A realistic self-serve band for a dedicated "AI session secret scanner" is roughly $5-15/dev/mo, and even that is hard to defend against free GitGuardian hooks; a team-governance/dashboard angle could reach ~$20-50/dev/mo but that sale needs security sign-off and slides toward enterprise, away from self-serve. No evidence found of anyone happily paying for a standalone AI-coding-secrets tool today.

### AI-coding tool spend & usage visibility/governance — let an eng manager/founder connect Claude Code/Cursor/Copilot and see cost + usage per developer, set budgets/alerts, and catch runaway spend. — score 6/10, self-serve fit medium
- who: Eng manager / VP Eng / founder-CTO (and increasingly the COO/finance partner) at a 10-150-developer startup or scale-up on usage-based AI-coding plans (Claude Code API, Cursor Business, Copilot) where the monthly bill is unpredictable and nobody owns it. Pain is acute specifically when teams move from flat seats to API/token billing ($150-600/dev/mo) and a single agent run or a non-dev (PM) can spike spend.
- intent: Actively SEARCHED-FOR, not a market you must educate. Eng managers literally post the question: r/ClaudeCode/r/claude 'My dev team is burning through Claude / Cursor credits like crazy... Any tools for tracking usage per dev? How do you prevent AI overuse?' The volume of SEO content built to capture this exact query (DX 'AI cost management report', Torii '5 Claude Code usage dashboards', CloudZero/Finout 'Claude Code pricing', getmaxim 'Top AI gateways for tracking coding agent spend', Holori/Mavvrik 'AI cost visibility tools') is itself proof of meaningful, monetizable search demand. The painkiller is real and people Google it; the catch is that free/native results often satisfy the search.
- existing: The named-tool gap is largely CLOSED and filling monthly. Free/OSS: ccusage, LiteLLM (per-key/per-team hard budget caps + attribution), New Relic AI Coding Observability/Preflight (open-source, Jun 2026), Claude Code Usage Monitor, cursor-usage-tracker. Native/first-party: Anthropic Console + Claude Code Analytics API (per-user sessions/commits/cost, admin usage caps), Cursor/Copilot admin dashboards, Cloudflare AI Gateway spend limits. Dedicated SaaS: StackSpend (5-min read-only connect, budgets/forecast/anomaly alerts across OpenAI/Anthropic/Cursor), Mavvrik, Holori, Revenium, Codensics (per-dev token quotas). Dev-intelligence/FinOps adjacents bolting it on: DX, Jellyfish (Cursor ROI), GitClear, WakaTime, CloudZero, Vantage, Harness, Torii (SaaS-mgmt angle: discovers shadow installs + per-employee attribution + overlap detection). Genuine remaining gap that CCGuard uniquely holds: work-vs-personal repo attribution and terminal-session content capture — but that is NOT the 'spend visibility' wedge as framed; that is a differentiator the marketing context itself flags as 'a market you must educate.'
- WTP: Budget for the SPEND is enormous and proven — $150-250/dev/mo typical at scale ($1,200+/mo for heavy Opus users), six-figure team bills (one team logged $47k in 3 days; r/EngineeringManagers projected $340k/yr), and AI coding now 2-4% of eng headcount budget (8-10% at AI-first teams per Larridin). That creates obvious ROI math for a control tool. BUT WTP for the governance TOOL itself is unproven and pressured toward $0 by free OSS and Anthropic's native analytics. Likely self-serve band: $0 free tier is table stakes, then ~$10-30/dev/mo or ~$99-499/team/mo — but you must out-feature free, which is hard for pure visibility. The enterprise FinOps players (Torii, DX, Jellyfish) capture real dollars but are sales-led, not self-serve. The self-serve middle is the thinnest part of the WTP curve here.

### "Work-vs-personal / acceptable-use of company AI coding tools" - a product telling employers whether company AI-coding seats (Claude Code, Cursor, Copilot, Codex) are used on personal/side projects vs sanctioned company work. — score 2/10, self-serve fit low
- who: Weakly felt, and by people who are NOT actively searching for it: (a) an eng manager / FinOps owner annoyed that paid seats burn tokens on non-company work, but they frame it as COST control, not work/personal attribution; (b) HR/legal worried about IP-ownership disputes when an employee ships a sellable side project built on a company seat (real but rare, reactive, handled by policy/contract not software); (c) a security/compliance lead who wants acceptable-use enforcement. None of these personas are visibly searching for or asking for a "is-this-personal-use" detector. By contrast, the loud, motivated persona is the EMPLOYEE protecting their side project from employer visibility - the opposite of a buyer.
- intent: Must be educated into existence on the buyer side. The actual search/ask volume runs the OTHER direction: developers asking "if I used my work Cursor/Copilot for a personal project, will they know / what are the implications" (r/ExperiencedDevs, r/developersIndia, r/github, HN "Tell HN: Cursor exposes side projects to your employer"). Employers do not search "detect personal use of company AI coding seats." Where employers do search, the query is "track employee AI usage" (productivity/shadow-AI framing, e.g. Teramind, Worklytics, Flowace, CNBC "almost every Fortune 500 is tracking overall AI usage") or "control AI credit spend" - not work-vs-personal coding attribution. So intent for THIS exact wedge is near-zero and would have to be manufactured via content marketing.
- existing: The differentiating "donut" (work vs personal repo attribution) has no named competitor - but that gap exists because there is little pull, not because it is hard. What people use today: (1) the AI tools' OWN admin analytics - Cursor "AI Edits by repository" + AI Code Tracking API (per-commit, per-repo, cannot be disabled), Copilot Enterprise and Claude Enterprise admin consoles, which already let an employer see which repos a seat touched, largely for free; (2) general AI-usage/productivity surveillance suites (Teramind $14-35/user, ActivTrak $10-19, Flowace, Worklytics) sold on the "track employee AI usage" job, not coding work/personal split, and widely seen as dev-toxic; (3) policy/contract (acceptable-use policy + IP-assignment clauses) which is how IP-ownership risk is actually managed today. So there IS a named-tool gap for "coding work-vs-personal attribution," but no demand is pulling for it and the cheap substitute (the vendor's own dashboard) is already in the buyer's hand.
- WTP: Little to no direct evidence of budget for THIS capability. There is clear budget adjacent to it - AI cost-governance/FinOps and AI/secrets security (GitGuardian ~$45k ACV, Snyk $52-98/dev, enterprise AI-coding bills tripled to ~$7M/yr) - but those dollars are attached to cost-control and leak-prevention, not to "tell me which seats did side projects." A standalone work/personal detector would most plausibly monetize only bundled as a line item, likely a $5-15/seat add-on (inferred), and even then the buyer can replicate the core signal from Cursor/Copilot's free admin view. WTP for the wedge as a lead product: low.

Recommend NOT leading with the generic "security & monitoring" positioning. Narrow to a sharper, self-serve-able painkiller (session-level secrets/PII leak detection, or the work-vs-personal attribution differentiator) where there is no named tool and the generic giants don't compete. — score 5/10, self-serve fit low
- who: Primary: DevSecOps / AppSec / platform-security engineer at a 20-200-dev company that has already rolled out Claude Code / Cursor and now has to answer "what are these agents actually doing on dev laptops, and can we prove it for SOC2?" Note: this acute buyer is an org-level, IT-involved buyer — not the lone self-serve card-payer the GTM requires.
- intent: Active searching, not education-required — but skewed. There is clear bottom-up search intent: "How do you handle security/monitoring of Claude Code in [org]?" (r/devops), "Am I overthinking Claude Code security or is this actually a risk?" (r/cybersecurity), "How is your company handling security around AI coding tools?" (r/devsecops), "How are regulated orgs actually letting engineers use Claude Code?" (r/devops), plus a flood of vendor SEO content (TrueFoundry, Maxim, MintMCP, Pluto, Northflank) which itself signals commercial search volume worth competing for. BUT the WTP is concentrated in exactly the segment that buys via procurement (regulated/enterprise, SOC2-driven — "SOC 2 for AI agents becomes a procurement requirement"), not via self-serve card. The self-serve segment's demonstrated WTP is mostly for cost-control, and the security-generic layer is being undercut to $0 by New Relic/Gryph/Dev Machine Guard.
